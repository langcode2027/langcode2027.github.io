Guardrails for code-mixed and transliterated prompts

Given a prompt sent to a code model, decide whether it is safe or unsafe. Every prompt is code-mixed (one of 10 languages mixed with English) or transliterated (English written in another script), with programming and security terms often kept in English.

The task

{{i:target}}Catch a malicious coding prompt in any language or script

{{i:inbox}}Input

One prompt to a code model, code-mixed with English or transliterated into the script of Arabic, Bengali, Chinese, Hebrew, Hindi, Japanese, Korean, Russian, Tamil or Thai.

→
{{i:tag}}Output

One label: S (safe) or U (unsafe).

{{i:book}}Background

Code-model safety filters are calibrated almost entirely on English. Rewrite a malicious request in another language, or spell it out in another script, keep the code keywords intact, and many filters stop working. In MALICE, the best classifier's accuracy fell from 0.93 on English to 0.21 on code-mixed malicious prompts, and even the most safety-aligned model tested produced about 3× more malicious code.

Safe prompts in this task are on the same security topics as the unsafe ones: how to detect an attack, defend a system or test one's own setup. A guardrail that flags every security word fails them, so a system has to read what each prompt asks for.

Findings from MALICE ↗ (Raihan, Meher, Dhingra, Zampieri; Findings of EMNLP 2026).
